# M9 Phase 2 implementation plan

## Scope and invariants

Extend the existing M9 private-preview renderer and Exploration draft path. Keep the legacy `COVER_NEWS` / `BODY_NEWS` input contract readable, preserve Standard/READY validation, fixed CTA bytes and ordering, FULL_BLEED/Pretendard styling, CPU MediaPipe, and DRAFT review-only behavior. Face/text overlap remains a diagnostic and never independently blocks a render. No Telegram send, Storage upload, production deployment, or paid image-analysis API is part of this work.

## Implementation steps

1. **Content-mode slide policy** — Add Exploration-only bounds (NEWS_UPDATE 2–4, ANALYSIS_CONTEXT 4–6, MATCH_CONTENT 3–5 content slides), pass mode into generation quality configuration, make prompts mode-aware, and allow the style validator to receive explicit Exploration bounds while keeping its current defaults. Add tests for all three modes, under-supported stories, duplicate padding, DRAFT, and unchanged READY behavior.
2. **Page-specific photo inputs** — Expand brief-to-photo requests and collection records to carry page numbers while retaining the two-slot legacy shape. Add content-hash/perceptual deduplication, per-page relevance selection, cache reuse, and explicit low-photo/zero-photo outcomes. Test unique images, resized/CDN duplicates, one-image fallback, unrelated candidates, and legacy input.
3. **Per-page render mapping and audit** — Validate additive page-photo media maps, fall back from legacy cover/body assets, pass independent crop/detection metadata to each page, and include URL/article/credit/hash/crop/scale/detection/reuse fields in the manifest. Keep CTA bytes unchanged and last. Make face overlap diagnostic-only.
4. **Korean typography and layout** — Centralize existing font and spacing settings; improve natural Korean wrapping, long-title handling, text bounding-box checks, density-aware spacing, and a small deterministic set of body layout variations. Preserve full-bleed backgrounds and gradient treatment.
5. **End-to-end and regression verification** — Render fixture-backed NEWS_UPDATE, ANALYSIS_CONTEXT, and MATCH_CONTENT samples plus at least one available real-article brief if present. Produce contact sheets and manifests, exercise scarce-image cases, run M9 and relevant Creative Generation/Telegram/READY regressions, and inspect the complete diff.
6. **PR #10 update** — Commit and fast-forward-push only to PR #10's existing head branch/base, preserving Draft status. Do not touch PR #8/#9, main, or production.

State any unavailable production/storage/network verification explicitly.
