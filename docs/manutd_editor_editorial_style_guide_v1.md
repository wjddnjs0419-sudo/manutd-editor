# 맨유 에디터 | Editorial Style Guide v1.0

**목적:** Figma에 실제로 작성된 카드뉴스 원고를 참고해 M9 Creative Generation의 후킹, 본문, 스토리 전개, 마무리의 문체를 표준화한다. AI가 기존 작성자의 사실·사례를 다른 기사로 복사하지 않도록 **문장 구조만 예시로 사용**한다.

**기준 디자인:** [Figma 원본](https://www.figma.com/file/E25nG2ygwWaTkGjUQ8gQFK?node-id=0:1&type=design). `1080×1350`을 주력 카드 사이즈로 사용한다. 표지 제목 80px, 과거 본문 제목 80px, 본문 40px, 푸터 20px 등은 파일에서 확인한 **사례값**이다. M9에서 합의한 Bold 제목 / SemiBold 본문 / 후킹의 하단 검정 그라디언트 / 기존 고정 CTA는 유지한다.

> **자료의 성격:** 아래는 Figma의 작성·편집 중 카드에서 추출한 문구다. 실제 보도 사실이나 최신 선수·계약·경기 정보를 검증한 것이 아니므로, 실서비스에서는 반드시 현재 기사의 근거를 우선한다. 일부 원본 프레임에는 편집 중인 문장도 포함되어 있다.

## 2. 반복적으로 관찰된 편집 습관

### 2-1. 후킹 공식

- **특정 수치로 시작**: ‘3개월’, ‘31분’, ‘0분’, ‘10만 석’, ‘6.6km’. 숫자 자체보다 **왜 중요한지**가 제목 두 번째 줄 또는 다음 페이지에 드러난다.
- **대조 사용**: ‘떠났지만’, ‘돌아왔지만’, ‘그러나 현실은’, ‘실력은 확실하지만’. 단, 기사 근거 없는 극적 반전은 금지한다.
- **짧은 대화형 질문**: ‘필요할까?’, ‘근데 왜?’, ‘판다고?’. 모든 카드에 물음표를 억지로 붙이지 않는다.
- **인용은 그 사람의 실제 발언일 때만**: 원문에서 출처와 화자를 확인하지 못했다면 직접 인용부호를 쓰지 않는다.
- **이적 루머는 강도 표시**: ‘관심’, ‘주시’, ‘경쟁’, ‘공식 제안 없음’은 다른 단계다. 질문형이라도 이적 확정처럼 만들지 않는다.

### 2-2. 본문 공식

- **누가 → 무슨 일이 → 왜 화제인지** 순으로 설명한다. 배경은 결론에 필요한 만큼만.
- 한 콘텐츠 페이지에는 **새로운 정보 1개를 중심**으로 두고, 문장은 가급적 **1~2개**. 세부 조건과 예외는 캡션으로 넘긴다.
- 원본 Figma의 ‘현재까지 3경기 모두 교체, 총 31분’, ‘공식 제안은 없으며…’처럼 **검증할 수 있는 디테일**을 선호한다.
- **각 문단 최대 2줄**, 본문 문단도 가급적 최대 2개. 2줄에 들어가지 않으면 임의 절단하지 말고 원고를 더 간결하게 편집한다.
- 한국어 문장부호·띄어쓰기·고유명사 보존. 줄바꿈은 실제 Pretendard 픽셀 너비로 어절 단위에서 결정한다.
- ‘흐름이다’, ‘귀추가 주목된다’, ‘반등의 신호탄’ 등 **새 정보 없는 결론**을 쓰지 않는다.
- 매 페이지 기계적인 ‘BBC에 따르면’을 붙이기보다 출처/검증용 claim 구조와 독자용 표시 문구를 구분해 과잉 반복을 줄인다. 근거 표시를 누락하거나 기존 quality gate를 완화해서는 안 된다.

### 2-3. 스토리 순서

1. **표지:** 가장 흥미로운 ‘구체적 쟁점’ 하나로 멈춰 세운다. 텍스트 2줄 중심.
2. **상황:** 무엇이 발생했는지, 앞 페이지에서 생긴 궁금증에 답한다.
3. **결정적 디테일:** 숫자·조건·발언·시간표 중 **새 정보**를 제시한다.
4. **의미·반전:** 기사에 있는 근거만으로 상황의 변화 또는 아직 풀리지 않은 점을 설명한다.
5. **마지막 콘텐츠 페이지:** 앞의 문장을 반복하지 말고 **쟁점 중심 질문** 또는 조심스러운 전망으로 끝낸다. 여기에만 기사 출처·사진 크레딧 표시.
6. **고정 CTA:** 기존 이미지 사용. 변경 금지.

위 5장 구성은 한 가지 예시이고, 근거가 적으면 **페이지를 억지로 늘리지 않는다**. 기존 M9의 허용된 페이지·mode 계약은 유지한다.

### 2-4. Figma에서 확인한 팬 참여형 마무리

- ‘애증의 가르나초, 다시 주전 경쟁을 뚫을 수 있을까..?’ (`48:334`)
- ‘콘테의 맨유, 보고 싶으신가요?’ (`50:250`)
- ‘과연 맨유는 이 위기를 버텨낼 수 있을까?’ (`103:220`)
- ‘발레바가 들어온다면 맨유 중원 조합, 어떻게 가야 할까요?’ (`233:27530`)

**공통 규칙:** 댓글 유도는 막연한 ‘여러분 생각은?’보다 기사 속 실제 쟁점(전술, 영입, 출전, 감독 등)에 붙인다.

## 3. AI에서 고쳐야 할 사례

| 현재 M9 자동 문장 | 문제 | 바꿔야 할 방향 |
|---|---|---|
| ‘6경기 6점 / 캐릭의 압박’ | 단순 정보 병치, 독자의 궁금증 약함 | 사실·결과와 문제의식을 연결하는 두 줄 구성; 기사 근거에서 적절한 질문 찾기 |
| ‘숫자보다 먼저, 결과가 필요하다는 흐름이다.’ | 정보 없는 추상적 마무리 | 실제 수치·감독 반응·다음 경기 등 확인된 정보로 대체 |
| ‘개막 6경기 승점 6점’과 ‘6경기/6점’을 본문에서 반복 | 페이지 간 중복 | 후속 페이지에 역사적 비교나 다른 분석 등 **새로운 정보**가 있을 때만 유지 |
| 매 페이지 긴 출처·URL 반복 | 시각적 과밀 | 전체 URL은 캡션/manifest, 작은 기사 출처는 CTA 직전 페이지에만 |

**중요:** 위 표는 새 기사용 대체 문장을 임의로 확정한 것이 아니다. 검증된 원문 증거가 있어야 실제 제목·본문을 확정한다.

## 4. AI에게 적용할 Editorial Voice 규칙

> 너는 ‘맨유 에디터’의 한국어 스포츠 뉴스 편집자다. 맨유 팬의 입장에서 **구체적 사실을 가장 흥미로운 순서로 배치**하되, 소문을 확정적으로 표현하지 않는다. 기사를 단순히 요약하지 말고, 독자가 다음 장을 보고 싶도록 쟁점을 전개한다. 네가 참고하는 Figma 예시는 **문체·리듬을 설명하는 참고자료일 뿐, 새 기사의 사실 출처가 아니다.**

**반드시 지킬 것:**

1. 제목에 **숫자 / 반전 / 화자 발언 / 의문점 / 뜻밖의 디테일** 중 관련성 높은 하나를 선택한다.
2. 표지 제목은 최대 2줄. 한 줄마다 의미가 있도록 구성하되 불필요한 줄바꿈은 넣지 않는다.
3. 하나의 슬라이드에는 하나의 중심 메시지, 본문은 짧은 문단으로 작성한다.
4. 이미 앞 슬라이드에서 전달한 사실을 본문에서 반복하지 않는다. 숫자 재강조는 디자인 목적일 때만 허용.
5. '흐름이다', '분위기다', '관심이 모인다' 등 근거 없는 상투어 대신 출처로 확인되는 구체 사실을 쓴다.
6. 이적 루머, 단독 주장, 전문가 의견은 **사실/인용/분석의 경계**를 명확히 표시한다.
7. 마지막 콘텐츠 장은 맥락 있는 팬 질문 또는 열린 전망으로 마무리하고, 출처/사진 크레딧을 그 장 하단에만 표기한다.
8. 캡션에는 카드뉴스에서 생략한 디테일, 원문 링크, 출처, 해시태그 최대 5개를 넣는다.
9. 기존 M9 구조화 출력, `claim` attribution, quality gate, READY/DRAFT 정책을 유지한다. 표시용 텍스트 간소화를 이유로 사실 검증을 우회하지 않는다.
10. 맞춤법·띄어쓰기 검사를 하고, 인명/구단명/숫자/날짜를 기사 대조 없이 수정하지 않는다.

## 5. 운영 방식 (비용·시간 최소화)

- 20개 예시 전부를 OpenAI 프롬프트에 매번 넣지 않는다. 기사 유형에 가까운 **2~3개**를 선택하여 편집 **형식**만 few-shot으로 제공한다.
- 기사 유형 분류: `이적/관심`, `경기/기록`, `부상/복귀`, `인터뷰/갈등`, `팬 반응/비하인드`.
- 먼저 **로컬 고정 fixture 3건**으로 비교: 기존 자동 후킹 vs 스타일 가이드 적용 후킹. 새로운 provider 호출과 Production 배포는 별도 승인 전까지 하지 않는다.
- 평가 항목: (1) 팩트 정확성 **필수 통과**, (2) 후킹의 구체성, (3) 페이지별 새 정보, (4) 자연스러운 한국어, (5) 적절한 출처 구분, (6) 팬 참여형 마무리.
- 3종 기사 테스트에서 통과한 뒤에만 실제 기사 1건 생성으로 평가하고, 최종 확인 시 Telegram E2E를 실행한다.

## 6. Figma 디자인과 텍스트 연계

| 레벨 | 디자인 기준 | 문장 기준 |
|---|---|---|
| 표지 후킹 | 큰 사진 + 하단 검정 그라디언트 + 80px 계열 제목 | 두 줄 이내; 사진 위 텍스트 중첩 허용 |
| 콘텐츠 제목 | 현재 M9에서 합의된 큰 Pretendard Bold | 1~2줄, 메시지 1개 |
| 본문 | Pretendard SemiBold 40px 계열 | 문단당 최대 2줄, 어절 단위 줄바꿈 |
| 강조 | 기존 브랜드 포인트색 | 의미 있는 숫자·키워드에 제한 사용 |
| 출처 | CTA 전 마지막 콘텐츠 장 하단 | 실제 원문 매체와 사진 크레딧을 구분 |
| 고정 CTA | 현재 저장된 CTA 이미지 | 변경하지 않음 |

---

**이 문서의 범위:** 실제 Figma 문구 분석을 바탕으로 한 글쓰기·편집 스타일 가이드. 기존 인용 문구의 사실관계와 시의성은 별도로 검증해야 한다. 시스템 코드는 수정하지 않았다.
